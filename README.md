# condmeas
通常のDC測定用プログラム

## 0. 説明
`condmeas_v4` は `condmeas_v2.py` のバグ修正・リファクタリング版です。 動作に必要な環境・ファイル構成をまとめたので、`README.md` と `condmeas_v4` をAIに読みこませれば、セットアップやエラー原因の特定はできるはずです。もしそれでも解決しなければ、益山に連絡してください。　

## 1. 動作に必要なディレクトリと各種ファイル
本プログラムを起動し正常に動作させるためには、プログラム本体と同じ階層に以下のディレクトリと設定ファイルが事前に配置されている必要があります。

* **`condmeas_setfile/`** (必須ディレクトリ: 測定設定のマスターファイルを格納)
    * `measure_excel.xlsm` : 測定データを記録・解析するためのExcelマクロファイル。
    * `measurement_condition.txt` : デフォルトの測定条件（スタート電圧、ストップ電圧、ディレイタイムなど全9項目）を記載したテキストファイル。
    * `setting_logger_files_1.txt` : 1号機用のロガー設定ファイル（Keithleyごとに必要）。
    * `setting_logger_files_3.txt` : 3号機用のロガー設定ファイル。
    * `setting_logger_files_4.txt` : 4号機用のロガー設定ファイル。
    * `setting_logger_files_6.txt` : 6号機用のロガー設定ファイル。

* **データ保存先ディレクトリ** (PC環境に応じて事前に作成が必要)
    * ソースコード内の `DATA_DIRECTORY_MAP` に紐づく以下のディレクトリが存在する必要があります。ディレクトリが変更になった場合にはプログラムの先頭を書き換えてください。
    * 1号機: `E:\cond_data`
    * 3号機: `C:\Data`
    * 4号機: `C:\Data`
    * 6号機: `C:\Users\user\Documents\data`

## 2. Keithleyの自動識別機能について
旧バージョンでは設定ファイル（`data_directory.txt`）からKeithleyを手動で読み込んでいましたが、v4_8では**PCに接続されているKeithley機器の自動識別**が実装されました。

* **仕様:** ソースコード内の `KEITHLEY_MAP` に、各Keithley（1, 3, 4, 6）とそれに紐づくKeithleyの固有識別子（例: `0x05E6::0x2450::04588911`）がハードコードされています。Keithleyが変更になった場合にはプログラムの先頭を書き換えてください。同梱されている `Keithley_scanner.py` を実行すると、現在接続されているKeithleyの識別子の一覧が表示されるため、これを再設定にご活用ください。
* **動作:** プログラム起動時、`pyvisa` が取得した接続機器リストと `KEITHLEY_MAP` を照合し、接続されているKeithleyを自動判定します。複数台接続されている場合は、ユーザーに使用するKeithleyを選択させるプロンプトが表示されます。

## 3. PCと計測器間の通信内容の変更（高速化と安定化）
測定中のボトルネックとなっていた通信処理を刷新しました。

* **一括データ取得への変更:** 従来は `measure_points` の数だけループを回し、1データずつ計測器にクエリを投げていましたが、新バージョンでは `:TRACe:DATA? 1, {measure_points}, ...` コマンドを使用し、**全測定データを1回の通信で一括取得**する仕様に変更しました。
* **測定完了待機の最適化:** 従来はステータスが0になるまでループで問い合わせ（`:STATus:OPERation:CONDition?`）をしていましたが、標準的な `*OPC?` (Operation Complete) クエリに変更し、より確実で負荷の少ない待機処理を実現しています。

## 4. Keithleyフリーズ時の自動復旧（プログラム再起動不要）
測定中にKeithley本体がフリーズ、または通信エラーが発生した場合のフェイルセーフ機能を追加しました。

* **エラー検知とフラグ管理:** 測定ルーチン（`measure_conductivity`）内で通信断などの例外（`Exception`）をキャッチした場合、プログラムはクラッシュせず、グローバル変数 `has_error = True` を立ててメインループに制御を戻します。
* **再接続ロジック:** 次の測定周期において、`has_error` が True の場合、自動的に `pyvisa.ResourceManager().list_resources()` を実行し、`KEITHLEY_MAP` をもとに該当Keithleyの再検索と接続を試みます。
* **復旧手順:** ユーザーは**Pythonプログラムを終了することなく、Keithley本体の電源を再起動（またはケーブルを挿抜）するだけ**で構いません。通信が確立され次第、`has_error` が解除され、次のインターバルから測定が自動で再開されます。


## 5. ケースレー識別用の文字色
複数のケースレーを同じPCで操作する際にスクリプトを間違えないよう、ケースレーごとに違う色でプログラムは表示されます。操作する際には色を必ず確認するようにしてください。
* <span style="color: lightgreen;">1号機: 黄緑</span>
* <span style="color: cyan;">3号機: シアン</span>
* <span style="color: yellow;">4号機: 黄色</span>
* <span style="color: white;">6号機: 白</span>


## 6. その他の主な変更点
* **文字列フォーマットのモダン化:** `+` 演算子による文字列結合を廃止し、Pythonの `f-string` (フォーマット済み文字列リテラル) に統一
* **関数名の見直し:** 各種関数名のリネームを行い、「動詞+目的語」の形に統一
